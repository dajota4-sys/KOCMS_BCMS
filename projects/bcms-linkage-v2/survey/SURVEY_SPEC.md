# 설문 이관 명세 (BCMS 앱용, V3)

문항이 확정되면 BCMS 앱의 설문 내용을 이 문항으로 교체한다. 앱의 현재 설문 형식을 알려 주면 이 JSON을 그 형식으로 변환하는 스크립트를 만든다.

## 파일
- `survey_items_v3.json`: 척도·품질 차원·프로세스 보유 문항·응답자 정보·문항 179개(구조화)
- `survey_items_v3.csv`: 같은 문항(UTF-8 BOM, 엑셀에서 바로 열림)

## 문항 필드
| 필드 | 뜻 |
|---|---|
| `id` | 문항 ID (`L01-TR` = 연결 L01의 추적성 문항, `DQ03` = 증빙성 종합 문항) |
| `part` | C 연결 / D 종합 / E 검증 |
| `link_id` | 연결 ID (종합·검증 문항은 비어 있음) |
| `quality_dimension`, `dimension_name` | CO 정합성 · TR 추적성 · EV 증빙성 · AC 책임성 · TM 최신성 · FC 환류폐쇄성 |
| `text` | 문항 문구 |
| `reverse_scored` | true이면 분석 시 `6 − 응답값`으로 뒤집음 |
| `scale` | `likert5_na9` (1~5, 9=해당 없음/모르겠음) |
| `relation_verb` | 연결의 관계동사 (예: 입력된다·활용된다) |
| `requires_process_ids` | 이 문항을 보여 주기 위해 운영 중이어야 하는 프로세스(Part B ID) |
| `evidence_type` | 연결의 증거유형 E1/E2/E3 (분석용, 응답자에게 비공개) |
| `basis_type`, `basis_quotes` | 문항 근거 구분과 인용 ID |

## 표시 규칙(권고)
1. **Part A·B 먼저**: 응답자 정보와 프로세스 보유 확인(22개, 1~4) 응답.
2. **조건부 표시**: 연결 문항은 `requires_process_ids`의 프로세스가 모두 1(운영)·2(부분)일 때만 표시. 아니면 건너뛰고 결측 처리.
3. **분할 배포**: 연결 문항이 163개이므로 응답자가 모두 답하기 어렵다. 응답자가 담당하는 프로세스가 포함된 연결만 제시하거나 영역(①~⑤) 단위로 나누어 배포한다.
4. **무작위 순서**: 문항 ID와 차원 이름은 숨기고 순서를 섞음. 주의확인 문항 `AC1`을 중간에 1개 삽입.
5. 모든 연결·종합·검증 문항에 응답 9(해당 없음/모르겠음)를 항상 제공.

## 점수 규칙
- 연결 점수 = 해당 연결에 적용된 차원 문항(5~6개)의 평균(9 제외, 최소 3문항 응답 시 산출)
- 차원 점수 = 응답자가 답한 연결 문항 중 같은 차원 문항의 평균(9 제외; 정합성·추적성·증빙성·책임성·최신성은 최소 5문항, 환류폐쇄성은 최소 2문항)
- 연결 품질 지수 = 6개 차원 점수의 평균(초기 동일 가중치; 예비조사 후 조정)
- DQ01~DQ07은 수렴 검증용으로 분리 보고
- 역문항(RV1~4, CR4)은 `6 − 값`으로 뒤집은 뒤 사용
- AC1에서 4가 아닌 응답자는 제외

## 주의
확정 전 문항이다. 외부 문헌 원문 확인, 전문가 내용타당도, 인지면담을 거쳐 문항과 차원 구성이 바뀔 수 있다. 앱에 올리기 전에 `data/items.json`을 최종본으로 갱신하고 `build_all.py`를 다시 실행해 이 파일들을 새로 만든다.
