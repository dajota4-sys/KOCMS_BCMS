# 설문 이관 명세 (BCMS 앱용)

문항이 확정되면 BCMS 앱의 설문 내용을 이 문항으로 교체한다. 앱의 현재 설문 형식을 알려 주면 이 JSON을 그 형식으로 변환하는 스크립트를 만든다.

## 파일
- `survey_items_v2.json`: 척도·프로세스 보유 문항·응답자 정보·문항 108개(구조화)
- `survey_items_v2.csv`: 같은 문항(UTF-8 BOM, 엑셀에서 바로 열림)

## 문항 필드
| 필드 | 뜻 |
|---|---|
| `id` | 문항 ID (`L01-R` = 연결 L01의 반영 문항) |
| `part` | C 연결 / D 종합 / E 검증 |
| `link_id`, `state` | 연결 ID와 상태(반영·확인·갱신). 종합·검증 문항은 비어 있음 |
| `text` | 문항 문구 |
| `reverse_scored` | true이면 분석 시 `6 − 응답값`으로 뒤집음 |
| `scale` | `likert5_na9` (1~5, 9=해당 없음/모르겠음) |
| `requires_process_ids` | 이 문항을 보여 주기 위해 운영 중이어야 하는 프로세스(Part B ID) |
| `evidence_type` | 연결의 증거유형 E1/E2/E3 (분석용, 응답자에게 비공개) |
| `basis_type`, `basis_quotes` | 문항 근거 구분과 인용 ID |

## 표시 규칙(권고)
1. **Part A·B 먼저**: 응답자 정보와 프로세스 보유 확인(22개, 1~4) 응답.
2. **조건부 표시**: 연결 문항은 `requires_process_ids`의 프로세스가 모두 1(운영)·2(부분)일 때만 표시. 아니면 건너뛰고 결측 처리.
3. **담당 영역 분할**: 응답자가 모든 연결을 알기 어려우므로 자신이 담당하는 프로세스가 포함된 연결만 제시하는 방식을 권장.
4. **무작위 순서**: 문항 ID와 상태 이름은 숨기고 순서를 섞음. 주의확인 문항 `AC1`을 중간에 1개 삽입.
5. 모든 연결·종합·검증 문항에 응답 9(해당 없음/모르겠음)를 항상 제공.

## 점수 규칙
- 연결 점수 = 해당 연결 R·V·U 3문항 평균(9 제외, 최소 2문항 응답 시 산출)
- 종합 연계성 지수 = 연결 점수들의 평균 (G01~G06은 수렴 검증용으로 분리 보고)
- 역문항(RV1~4, CR4)은 `6 − 값`으로 뒤집은 뒤 사용
- AC1에서 4가 아닌 응답자는 제외

## 주의
확정 전 문항이다. 전문가 내용타당도·인지면담을 거쳐 문항과 연결이 바뀔 수 있으므로, 앱에 올리기 전에 `data/items.json`을 최종본으로 갱신하고 `build_all.py`를 다시 실행해 이 파일들을 새로 만든다.
