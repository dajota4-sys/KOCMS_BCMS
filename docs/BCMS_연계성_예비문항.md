## 1. 측정 대상 정의 (온톨로지 층)

### 1.1 객체 (Białas의 class에 해당)

Arias Table 5의 **22개 BCMS 프로세스**를 객체로 사용한다. (Table 1의 23개 중 "BCMS 계획"은 1회성 프로젝트로 분류되어 제외됨 — Arias p.10)

| 약어 | 프로세스 | 범주(Arias Table 5) | 약어 | 프로세스 | 범주 |
|---|---|---|---|---|---|
| GOV | BC 거버넌스 | 관리 | EXE | BC 계획·절차 훈련·연습 | 핵심 |
| POL | BC 정책관리 | 핵심 | AWR | 인식·역량·교육 | 핵심 |
| REQ | 요구사항관리 | 핵심 | SUP | 공급망관리 | 핵심 |
| BIA | BIA·중요도 분석 | 핵심 | CHG | BC 변경관리 | 핵심 |
| RA | 리스크평가 | 핵심 | AUD | 내부감사 | 핵심 |
| STR | BC 전략·솔루션 결정·선정 | 핵심 | PERF | 성과평가 | 핵심 |
| IMP | 솔루션 이행관리 | 핵심 | CI | 지속적 개선 | 핵심 |
| PLAN | BC 계획·절차 개발 | 핵심 | DOC | 문서화된 정보 통제 | 지원 |
| INC | 사고·비상 대응 | 핵심 | RES | 자원관리 | 지원 |
| WARN | 경보·커뮤니케이션 | 핵심 | COM | 협의·커뮤니케이션 | 지원 |
| REC | 복구 | 핵심 | CRM | 고객관계관리 | 지원 |

Białas는 프로세스 외에 **산출물(artefact: 문서·기록·보고서)**도 별도 클래스로 둔다(예: `BIAreport`, `BCplan`, `trainingTrail`). 따라서 "연결"은 *A가 산출물을 만들고 B가 그것을 입력으로 쓰는 것*으로 정의한다.

### 1.2 관계 유형 (Białas의 object-type slot, domain→range)

| 관계 | 의미 | 예 |
|---|---|---|
| `informs` | A의 산출물이 B의 입력·기준이 됨 | REQ → BIA |
| `derivesFrom` | B가 A로부터 도출·구체화됨 | PLAN ← STR |
| `feedsBack` | B의 결과가 A의 개정·개선으로 되돌아감 | EXE → PLAN |
| `triggers` | A의 사건이 B의 수행을 개시함 | CHG → RA |

### 1.3 "연결" 자체를 객체로 (reification)

연결의 **상태**를 측정하려면 연결을 하나의 객체 `ProcessLink`로 두고 다음 data slot을 붙인다. (Białas가 `trainingEvaluat` 같은 data slot으로 평가 내용을 붙이는 방식의 응용)

| data slot | 뜻 | 증거의 예 | 문항 접미 |
|---|---|---|---|
| `reflected` **반영** | A의 산출물이 B의 활동·결정에 실제로 들어간다 | B의 문서에 A의 결과가 인용·반영됨 | **-R** |
| `verified` **확인** | 그 반영이 맞는지 점검·검토·대조한다 | 검토·승인·점검 기록 | **-V** |
| `updated` **갱신** | A 또는 B가 바뀌면 연결을 함께 고친다 | 개정 이력, 재검토 기록 | **-U** |

> 반영 → 확인 → 갱신은 **연결이 "있다 → 믿을 수 있다 → 살아 있다"**로 성숙하는 순서이므로, 단계가 높을수록 응답 평균이 낮아질 것이라는 가설을 §6에서 검증한다.

## 3. 응답 방식과 사용 규칙

- 척도: **1 전혀 그렇지 않다 – 2 그렇지 않다 – 3 보통이다 – 4 그렇다 – 5 매우 그렇다**, 별도 **9 = 해당 없음/모르겠음**
- 9번은 점수에서 결측 처리. (프로세스가 없거나 응답자가 모르는 경우를 "연결이 약함"과 구분하기 위함)
- 모든 문항은 "우리 조직에서는"으로 시작하며 **최근 12개월의 실제 운영 기준**으로 응답한다.
- 문항 ID(L01-R 등)는 응답자에게 숨기고, 문항 순서는 무작위로 섞는다.
- 응답자 1인이 25개 연결을 모두 알기 어려우므로, **자신이 담당하는 프로세스가 포함된 연결만 응답**하도록 영역별 분할 배포를 권장한다.

## 4. 예비문항 (Likert, 총 90문항)

### Part B. 프로세스 보유 확인 (22항목, 점수화하지 않음 — 선행 조건)

각 프로세스에 대해 **① 운영한다 ② 부분적으로 운영한다 ③ 운영하지 않는다 ④ 모르겠다** 중 선택.

## 5. 문항 작성 원칙 (점검표)

1. **두 객체 규칙**: 문항 문장 안에 연결의 양쪽 프로세스(또는 그 산출물)가 모두 나타나야 한다. 한쪽만 묻는 문항은 "프로세스 존재"를 재는 것이므로 제외.
2. **한 문항 한 상태**: 반영·확인·갱신 중 하나만 묻는다. ("반영하고 확인한다" 같은 이중 질문 금지)
3. **관찰 가능한 증거**: 기록·검토·개정·승인처럼 관찰 가능한 행위로 쓴다. ("잘 연결되어 있다" 같은 평가어 금지)
4. **실천 기준**: 의견이 아니라 최근 12개월의 실제 운영을 묻는다.
5. **용어 일관**: Arias Table 5의 프로세스 이름과 동일하게 사용.

## 6. 검증 계획 — "이 문항이 연계성을 재는가"

Białas는 ontology를 *testing*(구조 오류 점검)과 *validation*(실제 질의로 쓸모 확인)으로 나눈다(§2.7). 같은 구조로 문항을 검증한다.

### 6.1 구조 점검 (Białas의 testing에 해당)

| 점검 | 방법 | 통과 기준 |
|---|---|---|
| 추적성 | 모든 문항이 **정확히 1개 연결 × 1개 상태**에 매핑되는지 표(문항ID = 연결ID-상태)로 확인 | 매핑 누락·중복 0건 |
| 두 객체 규칙 | 문항 문장에 양쪽 객체가 모두 있는지 | 100% |
| 이중 질문 | 한 문항에 두 상태·두 행위가 섞였는지 | 0건 |
| CQ 환원 | 각 연결의 문항 3개가 §2의 CQ에 답하는 데 필요한 정보를 주는지 | 연결별 전원 일치 |

### 6.2 전문가 내용타당도 (Arias의 80% 합의 기준 차용)

- 패널: BC 관리자·컨설턴트·감사 전문가 **6~10인**.
- **(a) 연결 타당도**: "이 연결(A→B)은 실제 BCMS에서 성립하는가"를 4점 척도로 평가 → 연결별 I-CVI 산출.
- **(b) 문항 적합도**: 각 문항이 해당 연결·상태를 대표하는지 4점 척도 → 문항별 I-CVI.
- **(c) 맹검 재분류**: 문항 ID·연결 정보를 가리고 문항을 연결·상태에 분류하게 함 → 정답과의 일치율.
- 판정은 Arias(Figure 5)와 같은 3단계: **≥ 80% 일치 = 채택**, **20~80% = 토론 후 수정**, **< 20% = 삭제**. (CVI 관례 기준은 6~10인 패널에서 I-CVI ≥ 0.78)
- 등급 B 연결(L10, L15, L24)은 반드시 (a)를 통과해야 유지.

### 6.3 인지면담 (5~8인)

문항을 읽고 자기 말로 바꿔 설명하게 한다. 연결의 "양쪽"을 올바르게 이해하는지, "반영/확인/갱신"을 구분하는지 점검한다.

### 6.4 예비조사 통계 검증

표본은 문항 수(75+)를 고려해 **가능하면 150명 이상**을 권장한다(관례적 기준이며 절대 기준 아님).

| 질문 | 분석 | 기준(관례) |
|---|---|---|
| 연결별로 3문항이 한 덩어리인가? | 연결별 Cronbach α / McDonald ω, 문항-총점 상관 | α·ω ≥ .70, 문항-총점 r ≥ .30 |
| 상태(R/V/U)가 구분되는가? | 상태별 합성점수 간 상관, 확인적 요인분석(연결 단위 vs 상태 단위 모형 비교) | 상태 간 r < .85 (붕괴 아님) |
| **단계 가설**: 반영 > 확인 > 갱신 | 상태별 평균 비교(대응표본 검정) | 평균 순서 R ≥ V ≥ U |
| 응답이 일관적인가? | 역문항 RV1~4와 대응 정문항(G01, L01~03, L20, L14) 상관 | 유의한 음(−)의 상관 |
| 불성실 응답 | AC1 오답, 한 값만 반복 응답 | 제외 |
| "연계"를 재는가, "프로세스 존재"를 재는가? | 연계 점수 vs Part B 프로세스 보유 수의 관계 | 보유 수 통제 후에도 연계 점수가 준거를 설명 |
| 준거타당도 | 연계 점수 ↔ CR1~CR4 | 정(+)의 상관 |
| 집단 구별 | ISO 22301 인증 조직 vs 비인증 조직(A04), 실사고 경험 유무(A07) | 인증·경험 조직이 더 높음 |
| 종합 문항 수렴 | G01~G06 점수 ↔ 25개 연결 점수 평균 | 높은 상관 |

### 6.5 활용 검증 (Białas의 validation에 해당)

산출된 점수로 **§2의 CQ에 해당하는 진단 질문**에 답할 수 있는지 시험한다. 예: "연결 중 갱신(-U) 점수가 가장 낮은 곳은 어디인가?", "영역 ③에서 확인(-V)이 약한 연결은?" 이런 질의에 의미 있는 답이 나오지 않으면 문항 설계를 되돌려 수정한다.

### 6.6 최종 선별 규칙

- 연결별 3문항 중 α < .70이거나 문항-총점 r < .30인 문항은 수정 후 재검증.
- 연결 자체가 전문가 합의 < 80%이거나 응답 변별력이 없으면 해당 연결(3문항) 통째로 삭제.
- 최종본은 연결 수를 줄이더라도 **영역 ①~⑤가 모두 남도록** 유지.

## 7. 점수 산출 (안)

- 연결 점수 = 해당 3문항(R, V, U)의 평균 (9는 제외, 최소 2문항 응답 시 산출)
- 상태 점수 = 25개 연결의 R(또는 V, U) 평균
- 영역 점수 = 영역 내 연결 점수 평균
- 종합 연계성 지수 = 25개 연결 점수 평균 (G01~G06은 수렴 검증용으로 분리 보고)
- 해석: "연결이 있는가"는 **-R**, "믿을 수 있는가"는 **-V**, "살아 있는가"는 **-U** 점수가 말한다. 같은 연결이라도 R은 높고 U가 낮으면 *한 번 만든 연결이 방치된 상태*로 해석한다.

## 8. 문서 한계 요약

1. 25개 연결은 Arias의 서술에서 추출한 **가설적 연결**이며, Arias 자신은 연결을 실증 검증하지 않았다.
2. Arias의 조사 대상은 독일 BC 전문가 39명이므로 한국 조직에 그대로 적용하기 전 현지 전문가 검증이 필요하다. 저자들도 지리적 범위의 한계를 밝혔다(p.18).
3. Białas(2010)는 BS 25999 기반이며 현재 기준은 ISO 22301이다. 본 문서는 Białas의 **방법(클래스·관계·질의 검증)**만 차용했고 BS 25999 항목은 쓰지 않았다.
4. 반영·확인·갱신 3상태와 `ProcessLink` 객체화, 단계 가설은 **본 문서의 설계**이며 두 논문에 없다.
5. 통계 기준(α, CVI, 표본 크기)은 일반적 관례이며 연구 목적에 따라 조정한다.
